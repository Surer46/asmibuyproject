ID W: W1-03. Prioridad: P0. Estado: completado.

## Resultado y dependencias

Se implementó el sistema de acceso sencillo según el spec v2.1 con perfilado estricto (`ADMINISTRADOR` y `TRABAJADOR` fijos), sin roles configurables ni pantallas públicas de registro. Las contraseñas están protegidas con hash seguro `bcrypt` con salting; las sesiones residen en el servidor y guardan únicamente el hash SHA-256 del token en la base de datos (`sesiones.id`), viajando al cliente exclusivamente mediante cookies seguras `HttpOnly` y `SameSite=Lax`. Se eliminaron por completo las cuentas hardcodeadas y los fallbacks a memoria fuera de pruebas, garantizando que ante caída de base de datos se denieguen autenticaciones y escrituras con error 500. Se implementó validación de origen en CORS/CSRF y envío obligatorio de token CSRF en `AuthService.logout()`.

## Hallazgos y revisión

* Hallazgo Crítico resuelto: Se desactivaron las cuentas y el almacén en memoria en producción y fallos de BD; ante falla de BD se arroja error y se deniega autenticación.
* Hallazgo Alta resuelto: `sesiones.id` guarda únicamente el hash SHA-256 del identificador aleatorio de 32 bytes (64 caracteres hex).
* Hallazgo Alta resuelto: `logout()` incluye token CSRF y previene desincronización entre cliente y servidor.
* Batería automatizada `verificar-accesos-w1.ts` ejecutada con 41 pruebas exitosas y 0 fallos.
