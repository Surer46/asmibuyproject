## 2. Conexión con Supabase

### 2.1 Reglas

- `DATABASE_URL` solo vive en `app/backend/.env` (ignorado por git). No se copia a documentos, capturas, mensajes ni auditorías.
- El orquestador no lee ni escribe credenciales: el usuario configura el archivo y el orquestador ejecuta comandos que no imprimen la conexión.
- Las pruebas destructivas o de concurrencia siguen en la base local `asmibuy_test_*`. En Supabase solo se ejecutan el migrador, cuentas nominales, datos de QA identificables y los recorridos funcionales.

### 2.2 Pasos del usuario

1. En Supabase: **Project Settings → Database → Connection string**. Si el equipo no tiene IPv6, usar el **Session pooler** (puerto 5432), no la conexión directa `db.<proyecto>.supabase.co`, que en el plan Free solo responde por IPv6.
2. Copiar `app/backend/.env.example` a `app/backend/.env` y poner la cadena real en `DATABASE_URL`.
3. Cambiar `SESSION_SECRET` por un valor aleatorio propio; no usar el del ejemplo.
4. Certificado: descargar el certificado SSL del proyecto (Database Settings → SSL). Pendiente del integrante 1: `database.ts` pasa `DB_SSL_CA` directamente como **contenido PEM**, mientras `.env.example` lo describe como **ruta**. Hasta que se aclare, poner el contenido PEM en una sola línea con `\n`, o esperar la corrección del integrante 1. No usar `DB_SSL_REJECT_UNAUTHORIZED=false` salvo como diagnóstico temporal registrado.
5. Crear las cuentas de QA el propio usuario (la utilidad recibe la contraseña como argumento y queda en el historial de la terminal):

```bash
node app/backend/dist/scripts/mantenimiento-cuentas.js crear "Admin QA" admin.qa@asmibuy.invalid <contraseña> ADMINISTRADOR
```
